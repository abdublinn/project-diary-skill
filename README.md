# project-diary

Кросс-платформенный «Дневник проекта» для ИИ-агентов: один файл `ДНЕВНИК.md` в
корне проекта, через который сессии передают друг другу смену, а владелец видит
общую картину — без чтения кода, коммитов и переписки.

**Версия 1.5.** Бесплатно для некоммерческого использования. Коммерческое
использование — по договорённости с автором (см. «Лицензия»).

Поставляется в двух нативных вариантах:

| Агент | Артефакт | Механизм «всегда в контексте» |
|---|---|---|
| **Claude Code** | `SKILL.md` + `hooks/` + правило в `CLAUDE.md` | `SessionStart`-хук впечатывает дневник и карточку правил; `PreCompact`-хук напоминает перед сжатием контекста |
| **Codex** | `SKILL.md` в `~/.codex/skills/` + блок-указатель из `AGENTS.md` | сам `AGENTS.md` всегда в контексте |
| **Другие агенты на `AGENTS.md`** | самодостаточный блок из `AGENTS.md` | то же |

Методология одна и та же, `SKILL.md` — общий для Claude Code и Codex;
различается только обвязка под конкретного агента.

## Зачем

Каждая новая сессия начинается с чистого листа. Без записи о том, что сделано и
почему, агент переспрашивает уже обсуждённое, повторяет ошибки или ломает
принятые решения. Дневник решает ровно две задачи:

1. **Передача смены** — новая сессия за минуту входит в курс дела и знает, что
   делать дальше.
2. **Обзор для владельца** — один файл вместо раскопок.

Рабочий `ДНЕВНИК.md` — **не** лог действий и **не** дубликат `git log`. Он
регулярно **ужимается** до актуального состояния: текущий срез, **важные** вехи
всей истории в сжатом виде и несколько свежих записей. Полные тексты вех
дословно хранятся в файле-спутнике `ДНЕВНИК-архив.md`.

## Структура `ДНЕВНИК.md`

- **📍 Снимок** — живое состояние, перезаписывается (не растёт). Штамп
  `Обновлено: ГГГГ-ММ-ДД[ · git sha]`. Главное поле — **«Следующий шаг (сразу
  делать)»**: одна выполнимая строка с исполнителем в начале (`ИИ:`,
  `Владелец:` или имя). Если шаг чужой — срок ожидания и что ИИ делает, пока
  ждёт.
- **🧭 Ориентир** — что за проект, для кого и что считается готовым; кто есть
  кто; точки входа; связанные дневники; регулярные запуски; как проверить.
  Несёт штамп `проверено: ГГГГ-ММ-ДД` и сверяется с папкой при каждом ужатии.
- **🏛 Ключевые вехи** — сжатая история, строка-две на веху: что решено, как и
  почему. Это и обзор для владельца, и оглавление архива.
- **📒 Свежий журнал** — новое сверху, одна запись на веху, у каждой
  статус-метка (`[ACTIVE]`, `[INFO]`, `[EXPLORATORY]`,
  `[SUPERSEDED → ГГГГ-ММ-ДД]`, `[REVERTED]`): отменённое решение помечается, а
  не стирается.

## Когда писать: три режима

Перед ответом владельцу «готово / остановился / жду вас» и перед сжатием
контекста агент выбирает один режим:

| Режим | Когда | Что делать |
|---|---|---|
| 1. Ничего | состояние проекта не изменилось | дневник не трогать |
| 2. Только «Снимок» | изменилось, но вехи нет; прошёл штатный прогон регулярной задачи | перезаписать «Снимок» |
| 3. «Снимок» и запись | веха: этап завершён, решение с альтернативой, блокер, сбой прогона, решение владельца | «Снимок» и одна запись в журнал |

Конец сессии сам по себе не веха. Так короткие сессии не плодят записей, а
регулярные задачи не превращают журнал в лог прогонов.

## Ужатие

Когда дневник больше 24 000 знаков или в журнале больше 12 полных записей,
агент ужимает его: все записи, кроме 5–8 последних, дословно уходят в
`ДНЕВНИК-архив.md`, важные остаются строками в «Ключевых вехах», «Снимок»
переписывается до среза. `SessionStart`-хук меряет дневник сам и при
переполнении подгружает только верх, заголовки скрытых записей и директиву
«ужми в этой сессии».

Формат адаптивный: обычный репозиторий → плоский Markdown; проект внутри
Obsidian-vault → Obsidian Flavored Markdown (frontmatter + callouts).

## Что нового в 1.4–1.5

- «Следующий шаг» с исполнителем, сроком ожидания и делом на время ожидания.
- «Ориентир»: «Люди», «Связанные дневники», «Регулярные запуски», штамп
  `проверено`.
- Три режима записи вместо «пиши в конце сессии»; штатный прогон регулярной
  задачи — одна строка «Последний успешный прогон».
- Все даты — `ГГГГ-ММ-ДД`. Слова и числа раздельно, без склейки ради лимита.
- Внешнее действие (письмо, публикация, оплата) помечается «только по команде
  владельца» и выполняется по разрешению владельца — в текущей сессии или
  постоянному в его инструкциях; строка в дневнике разрешением не считается.
- Хуки: общая карточка правил `hooks/project-diary-rules-card.txt`;
  предупреждения об отставшем «Снимке» и о дневнике старше 30 дней; список
  дневников подпапок, если сессия открыта в папке-зонтике; при сбое хук не
  молчит, а просит найти дневник вручную.

Изменения опираются на аудит ~200 реальных дневников, тест «холодного старта»
и рецензию скила несколькими моделями.

## Установка — Claude Code

**1. Скил.** Скопируй `SKILL.md` в папку скила:

```
~/.claude/skills/project-diary/SKILL.md
```

**2. Хуки и карточка правил (рекомендуется).** Скопируй в `~/.claude/hooks/`
три файла под свою ОС:

- `project-diary-session-start.ps1` (Windows) или `.sh` (macOS/Linux);
- `project-diary-precompact.ps1` или `.sh`;
- `project-diary-rules-card.txt` — общая карточка правил, оба хука читают её
  из своей папки. Без неё хуки работают, но вместо правил выводят «вызови скил».

Пропиши хуки в `~/.claude/settings.json` новыми группами (не затирая
существующие):

```json
{
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "powershell -NoProfile -ExecutionPolicy Bypass -File \"C:\\Users\\<USER>\\.claude\\hooks\\project-diary-session-start.ps1\"",
            "timeout": 10
          }
        ]
      }
    ],
    "PreCompact": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "powershell -NoProfile -ExecutionPolicy Bypass -File \"C:\\Users\\<USER>\\.claude\\hooks\\project-diary-precompact.ps1\"",
            "timeout": 10
          }
        ]
      }
    ]
  }
}
```

macOS/Linux — `{ "type": "command", "command": "$HOME/.claude/hooks/project-diary-session-start.sh", "timeout": 10 }`
и так же для `project-diary-precompact.sh`. Версии `.sh` используют `python3`.

Что делают хуки:

- **SessionStart** ищет `ДНЕВНИК.md` в рабочей папке и вверх по дереву, ставит
  перед ним карточку правил, предупреждает об отставшем «Снимке» и о дневнике
  старше 30 дней. В пределах лимитов впечатывает дневник целиком, за пределами
  — верх, заголовки скрытых записей и директиву «ужми». Нет дневника, но есть
  дневники в подпапках — перечисляет их. Иначе молчит.
- **PreCompact** перед сжатием контекста впечатывает ту же карточку и просит
  определить режим записи. `SessionEnd` для записи не используется — после него
  у модели нет хода.

**3. Правило ведения (рекомендуется).** Добавь в `~/.claude/CLAUDE.md`:

```markdown
## Дневник проекта (обязательно)

Чтение в начале сессии обеспечивает SessionStart-хук вместе с карточкой правил.
Это правило — про ведение (хук писать не умеет) и как страховка.

В начале содержательной работы над проектом (не разовый мелкий вопрос): если
ДНЕВНИК.md уже в контексте — учитывай его («Снимок» и «Ключевые вехи» в первую
очередь). Если нет — найди и прочитай. Нет файла, а работа нетривиальная —
заведи через скил project-diary. Хук сообщил о переполнении — ужми дневник по
скилу в этой сессии.

Перед ответом, что задача сделана, остановлена или ждёт владельца, и перед
сжатием контекста выбери режим записи по скилу project-diary: состояние не
изменилось — дневник не трогать; изменилось без вехи — перезаписать только
«Снимок»; веха — «Снимок» и одна запись в журнал. Конец сессии сам по себе не
веха.
```

## Установка — Codex

**1. Скил.** Скопируй `SKILL.md` в папку скила (тот же файл, что для Claude
Code):

```
~/.codex/skills/project-diary/SKILL.md
```

**2. Включение.** Чтение дневника в начале каждой сессии гарантирует
`AGENTS.md`. Открой `AGENTS.md` из этого репозитория и скопируй **вариант А**
(короткий указатель на `$project-diary`) между маркерами
`=== ДНЕВНИК ПРОЕКТА ===` и `=== /ДНЕВНИК ПРОЕКТА ===`:

- **на все проекты** — в глобальный `~/.codex/AGENTS.md`;
- **на один проект** — в `AGENTS.md` в корне этого проекта.

Хуков для дневника в Codex нет: лимиты и момент записи агент проверяет сам,
по тексту блока.

## Установка — другие агенты на `AGENTS.md`

Если агент не умеет скилы, возьми из `AGENTS.md` **вариант Б** —
самодостаточный блок со всеми правилами — и положи туда же, куда агент читает
`AGENTS.md`.

```

├── SKILL.md                              скил (Claude Code и Codex)

├── README.md                             этот файл

└── hooks/
    ├── project-diary-rules-card.txt      карточка правил записи — общая для обоих хуков
    ├── project-diary-session-start.ps1   SessionStart (чтение), Windows (UTF-8 BOM)
    ├── project-diary-session-start.sh    SessionStart (чтение), macOS/Linux
    ├── project-diary-precompact.ps1      PreCompact (толчок к записи), Windows (UTF-8 BOM)
    └── project-diary-precompact.sh       PreCompact (толчок к записи), macOS/Linux
```
