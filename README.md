# project-diary

Кросс-платформенный «Дневник проекта» для ИИ-агентов: один файл `ДНЕВНИК.md` в
корне проекта, через который сессии передают друг другу смену, а владелец видит
общую картину — без чтения кода, коммитов и переписки.

Поставляется в двух нативных вариантах:

| Агент | Артефакт | Механизм «всегда в контексте» |
|---|---|---|
| **Claude Code** | `SKILL.md` + `hooks/` + правило в `CLAUDE.md` | `SessionStart`-хук впечатывает дневник; правило в `CLAUDE.md` про ведение |
| **Codex** | `SKILL.md` в `~/.codex/skills/` + блок-указатель из `AGENTS.md` | сам `AGENTS.md` всегда в контексте |
| **Другие агенты на `AGENTS.md`** | самодостаточный блок из `AGENTS.md` | то же |

Методология одна и та же, `SKILL.md` — общий для Claude Code и Codex;
различается только обвязка под конкретного агента.

---

## Зачем

Каждая новая сессия начинается с чистого листа. Без записи о том, что сделано и
почему, агент переспрашивает уже обсуждённое, повторяет ошибки или ломает
принятые решения. Дневник решает ровно две задачи:

1. **Передача смены** — новая сессия за минуту входит в курс дела.
2. **Обзор для владельца** — один файл вместо раскопок.

Рабочий `ДНЕВНИК.md` — **не** лог действий и **не** дубликат `git log`. Он
регулярно **ужимается** до актуального состояния: остаются текущий срез,
**важные** вехи всей истории в сжатом виде и несколько свежих записей. Отбор —
по важности, а не по возрасту: старое, но действующее решение остаётся на виду.
Полные тексты вех дословно хранятся в файле-спутнике `ДНЕВНИК-архив.md`, и
агент идёт туда, только когда задача требует.

## Структура `ДНЕВНИК.md`

- **📍 Снимок** — живое состояние, перезаписывается (не растёт). Несёт штамп
  свежести `Обновлено: <дата>[ · git sha]` и первой строкой — **«Следующий шаг
  (сразу делать)»**: одно копируемое действие для мгновенной передачи смены.
- **🧭 Ориентир** — что за проект, точки входа, как проверить (меняется редко).
- **🏛 Ключевые вехи** — сжатая история проекта, строка-две на веху: что
  сделано или решено, как и почему. Это и обзор для владельца, и оглавление
  архива: по дате из строки полная запись находится в `ДНЕВНИК-архив.md`.
- **📒 Свежий журнал** — append-only, новое сверху, одна запись на веху, решения
  с «почему». У каждой вехи статус-метка (`[ACTIVE]`, `[INFO]`, `[EXPLORATORY]`,
  `[SUPERSEDED → дата]`, `[REVERTED]`): отменённое решение помечается, а не
  стирается, и новая сессия не примет его за действующее.

**Ужатие.** Когда дневник больше 24 000 знаков или в журнале больше 12 полных
записей, агент ужимает его: все записи, кроме 5–8 последних, дословно уходят в
`ДНЕВНИК-архив.md`, важные из них остаются строками в «Ключевых вехах»,
«Снимок» переписывается до среза. Лимиты в знаках, а не в строках: длинный
абзац в одну строку — тот же объём. Запуск не держится на памяти модели:
`SessionStart`-хук меряет дневник и при переполнении подгружает только верх
(Снимок, Осторожно, Ориентир, Ключевые вехи) с директивой «ужми в этой сессии».

Формат адаптивный: обычный репозиторий → плоский Markdown; проект внутри
Obsidian-vault → Obsidian Flavored Markdown (frontmatter + callouts).

## Установка — Claude Code

**1. Скил.** Скопируй `SKILL.md` в папку скила:

```
~/.claude/skills/project-diary/SKILL.md
```

**2. Хук чтения (рекомендуется).** Скопируй хук под свою ОС в `~/.claude/hooks/`
и пропиши в `~/.claude/settings.json` новой группой внутри `hooks.SessionStart`
(не затирая существующие группы):

```json
{
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "powershell -NoProfile -ExecutionPolicy Bypass -File \"C:\\Users\\<USER>\\.claude\\hooks\\project-diary-session-start.ps1\"",
            "timeout": 10
          }
        ]
      }
    ]
  }
}
```

macOS/Linux — используй `hooks/project-diary-session-start.sh`:

```json
{ "type": "command", "command": "$HOME/.claude/hooks/project-diary-session-start.sh", "timeout": 10 }
```

Хук при старте сессии сам ищет `ДНЕВНИК.md` в рабочей папке и вверх по дереву и
меряет его. В пределах лимитов (24 000 знаков, 12 полных записей) — впечатывает
целиком; за пределами — только верх и директиву «выполни Ужатие в этой
сессии». Нет файла — молчит. Версия `.sh` для контроля размера использует
`python3` (без него — старое поведение, первые 200 строк).

**3. Правило ведения (рекомендуется).** Добавь в `~/.claude/CLAUDE.md`:

```markdown
## Дневник проекта (обязательно)

Чтение в начале сессии обеспечивает SessionStart-хук. Это правило — про ведение
(хук писать не умеет) и как страховка.

В начале содержательной работы над проектом (не разовый мелкий вопрос): если
ДНЕВНИК.md уже в контексте — учитывай его («Снимок» и «Ключевые вехи» в первую
очередь). Если нет — найди и прочитай. Нет файла, а работа нетривиальная —
заведи через скил project-diary. Хук сообщил о переполнении — ужми дневник по
скилу в этой сессии.

По ходу работы обновляй ДНЕВНИК.md через скил project-diary при: завершении
вехи, нетривиальном решении (с «почему»), блокере, в конце сессии. Не на каждую
правку.
```

**4. Хук записи (PreCompact, рекомендуется).** Скопируй
`hooks/project-diary-precompact.ps1` (или `.sh`) в `~/.claude/hooks/` и пропиши
в `~/.claude/settings.json` событием `hooks.PreCompact`:

```json
{
  "hooks": {
    "PreCompact": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "powershell -NoProfile -ExecutionPolicy Bypass -File \"C:\\Users\\<USER>\\.claude\\hooks\\project-diary-precompact.ps1\"",
            "timeout": 10
          }
        ]
      }
    ]
  }
}
```

macOS/Linux — `{ "type": "command", "command": "$HOME/.claude/hooks/project-diary-precompact.sh", "timeout": 10 }`.

Срабатывает ровно перед сжатием контекста: если есть `ДНЕВНИК.md` — впечатывает
директиву «зафиксируй веху сейчас, до сжатия» (а если дневник за лимитами —
ещё и «ужми его в этой сессии»); если дневника нет, но это проект — «заведи»;
иначе молчит. `SessionEnd` для записи намеренно не используется — после
него у модели нет хода.

> Почему так: чтение можно сделать полностью детерминированным (SessionStart-хук).
> Запись — нет, это суждение модели; но PreCompact-хук бьёт директивой ровно в
> момент риска потери контекста, а правило в CLAUDE.md ведёт обычную запись и
> страхует, если хук не отработал.

## Установка — Codex

**1. Скил.** Скопируй `SKILL.md` в папку скила (тот же файл, что для Claude
Code):

```
~/.codex/skills/project-diary/SKILL.md
```

**2. Включение.** Сам скил Codex подхватывает по описанию, но чтение дневника в
начале каждой сессии нужно гарантировать: механизмом «всегда в контексте»
служит `AGENTS.md`. Открой `AGENTS.md` из этого репозитория и скопируй
**вариант А** (короткий указатель на `$project-diary`) между маркерами
`=== ДНЕВНИК ПРОЕКТА ===` и `=== /ДНЕВНИК ПРОЕКТА ===`:

- **на все проекты** — в глобальный `~/.codex/AGENTS.md`;
- **на один проект** — в `AGENTS.md` в корне этого проекта.

Хуки в Codex есть, но для дневника не настроены: напоминание «запиши веху
перед сжатием контекста» держится на тексте блока.

## Установка — другие агенты на `AGENTS.md`

Если агент не умеет скилы, возьми из `AGENTS.md` **вариант Б** —
самодостаточный блок со всеми правилами — и положи туда же, куда агент читает
`AGENTS.md`.

```
└── hooks/

    ├── project-diary-session-start.sh    SessionStart (чтение), macOS/Linux
    ├── project-diary-precompact.ps1      PreCompact (запись-толчок), Windows (UTF-8 BOM)
    └── project-diary-precompact.sh       PreCompact (запись-толчок), macOS/Linux
```
